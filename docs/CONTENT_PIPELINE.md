# LIFE QUEST Content Pipeline

LIFE QUESTは、思いついた要素を即実装するのではなく、未来コンテンツとして蓄積し、必要になった時に安全にLIVEへ昇格させる。

## 状態
- IDEA: 名前と一言だけ。まだ仕様を固定しない。
- CONCEPT: 用途、他システムとの接続、世界内での役割まで決まった状態。
- PREPARED: 安定ID、基本メタデータ、assetKeyなどが揃い、実装候補として内部に保存済み。ただしゲームには出さない。
- LIVE: 現在のゲーム、セーブ、ドロップ、図鑑、Chapter等に正式接続済み。

## 最重要ルール
PREPAREDを増やしても、既存のセーブ形式・図鑑母数・Chapter達成条件・ドロップテーブルは自動で変更しない。LIVEへ昇格する時だけ、既存セーブとの互換性と移行方法を確認して実装する。

## Asset Library方針
コンテンツ本体は安定IDを正本とし、画像は付属物として扱う。たとえば `fish/ito` が資産キーで、将来画像を差し替えても魚IDは変えない。未実装画像を大量に持っていても、ゲーム起動時に全部ロードせず、必要な地域・画面の資産だけを読む設計にする。

## 魚マスター
`src/content/fishMaster.ts` を魚の未来資産台帳とする。

現在は100種を登録済み。
- LIVE: 12種。現行ゲームのセーブ、釣り、図鑑に接続済み。
- PREPARED: 88種。将来用で、現行ゲームにはまだ出現しない。

各魚は安定ID、日本語名、実在/幻想、環境、レア度、releaseGroup、将来用途、assetKey、状態を持つ。用途候補は交易、料理、博物館、依頼、水槽。季節・時間・天候・サイズ・価格などは地域や経済設計が固まった段階で追加する。

## 未来資産カタログ
魚に加えて、地域、建物、天候、季節イベント、素材、農作物/畜産物、料理/加工レシピ、交易品、機関車/貨車/客車、路線、NPC、クエスト雛形、実績、装備、研究、博物館展示、宝物を内部マスターとして追加済み。詳細と件数は `CONTENT_CATALOG.md` と `src/content/contentManifest.ts` を参照する。

これらは大量にPREPAREDしていても、必要になったものだけLIVEへ昇格する。数値バランスが未確定な未来要素は用途タグや設計ヒントに留め、将来の設計を不用意に固定しない。

## LIVE昇格時の確認
1. 既存セーブを壊さないか
2. 入手場所と解放条件が決まっているか
3. 何に使えるかが最低2方向以上あるか、または収集上の明確な価値があるか
4. 図鑑/博物館/交易/料理等のどこに接続するか
5. 画像資産をいつロードするか
6. バランス、Chapter、実績への影響
7. docsとCHANGELOGの更新


## Cloudflare版での運用
- GitHub `life-quest/src/content/` を画像非依存コンテンツ台帳の保存先とする。
- `assetKey` は画像未作成でも維持する。
- PREPAREDデータはUI、ドロップ、図鑑母数、Chapter条件へ自動接続しない。
- Cloudflare版でLIVEへ昇格する際はLUNA COREのcanonical GameState・既存セーブ互換性を先に確認する。
